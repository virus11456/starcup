## 續作：大廳載入與邀請穩定性

- 首頁原本把服務失敗仍標成「正在連接服務」，且讀取中或失敗時會顯示「目前沒有公開房間」。現在區分讀取中、成功空清單、可加入清單與失敗；失敗顯示可重試的繁體中文訊息，不保留舊房間按鈕。
- 首頁沿用既有單一請求管理：讀取期間停用重新整理，15 秒中止逾時請求，離頁時取消；遲到回應不再恢復舊清單或解除新請求的鎖定。沒有背景輪詢或自動重試。
- 整理舊 `grail-room-v1` 指標時，瀏覽器若拒絕 localStorage 存取，仍可繼續房間邀請轉跳與大廳讀取；不清除現行座位憑證或偏好。
- 房間回應先驗證格式，只使用公開顯示欄位；配額、登入、未設定服務及非 JSON 錯誤不會被當作正常空房間。加入固定「輸入邀請碼」入口，房間工具列可換行。
- 最終 `npm run verify:local` exit 0：**159 項**（86 應用、68 引擎、5 本機 Cloudflare runtime），建置與型別檢查成功。新增 8 項覆蓋儲存阻擋、回應／取消及真正 Lobby 元件的 React SSR 狀態；SSR 不是瀏覽器操作或畫面驗收。紀錄 `outputs/lobby-reliability-verify.log`。

## 實際觀察

- 在 Cloudflare 正式首頁的瀏覽器中確認，`.portal-home` 直接位於 `body` 下，沒有 `main` 與 `.portal-mode` 容器；但原本的寬度、背景、左右留白規則仍只套用 `.portal-mode > .main-shell > main`。桌面 1363px 視窗的內容區左側為 0，寬 1348px；390px 檢查框內內容左側同樣為 0。
- 使用正式 `/qa-layout.html` 的 844×390 橫向尺寸確認，首頁可用寬度 829px、scrollWidth 880px，右側聖女圖卡伸至 x=880，出現橫向捲軸。390px 窄版則依靠裁切把側邊圖卡切掉。這是實際 DOM 與截圖觀察，不是推測快取問題。
- 原本首頁上方只有單人入口與角色技能連結；多人按鈕在下方模式區，不夠容易找到。

## 修改

- 首頁建立明確的 `.portal-mode > main.portal-content`，直接套用 1440px 最大寬度與左右留白；標頭對齊內容。服務錯誤訊息使用首頁自己的通知樣式，放在相同內容容器裡。
- 角色展示以容器比例安排三張圖卡、圓環與星杯標記，移除固定像素位移後再縮放、負邊界的做法。1000px 以下改為單欄，裝飾裁切僅限展示區，不靠整頁隱藏橫向捲動遮住內容。
- 模式卡片依可用寬度排列，卡內文字與標籤可換行，標籤與箭頭預留空間；長房名可換行，房間數與按鈕不被擠出；窄螢幕導覽允許換行。
- 首頁主按鈕直接並列「單人對電腦」`/full` 與「多人對戰」`/online`；頂部導覽也有多人對戰，原本下方多人模式卡改為正常連結，角色技能入口保留在主按鈕下方。
