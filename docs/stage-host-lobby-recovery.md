# 房主等待室恢復與防誤關

2026-10-26，本機開發階段。僅備份 `fix/relay-recovery-20261026`；沒有推 `cloudflare-migration` 或 `main`，沒有部署、建立正式測試房或刪除 Vercel。正式站仍是直式卡牌版本 `e639f6a`，前次驗收見 [直式卡牌階段](stage-portrait-cards.md)。

## 問題與修正

舊版同房主的新連線會直接將房間設為 closed，即使原分頁仍在對戰。本次改成拒絕重複連線，原房間和原連線繼續運作。

未開始選角的房間新增「恢復等待房間」：原房主分頁離線滿 60 秒、原席位憑證仍存在時，可以保留同一房碼和已加入的成員。只讀預檢不寫入房間／大廳；實際 attach 再次檢查，避免預檢後已開局卻被覆寫。恢復不重新建立房間或消耗新開房名額。

開始按鈕先確認 Cloudflare 已保存開局狀態，再讓固定原生引擎進入選角。網路錯誤保留按鈕，回覆遺失可重試；連點不重複開始。開始與恢復的請求以目前房主連線和 waiting／playing 狀態互斥，任一先完成，另一個舊操作即遭拒絕。

恢復後清空舊中繼訊息，保留遞增序號；客人以原席位重新載入原生等待室。舊連線的結果、ack、WebSocket 暫存心跳不會進入新等待室。房主應等朋友重新入座後再開局；不保證離線中的人已恢復原生座位。

## 邊界

- 只支援以新開局協定建立的等待室。舊版房間、已開始選角／對戰、已結束房間均不能重建。
- 恢復依賴同分頁 sessionStorage 中的原席位憑證；清掉資料或另開沒有憑證的分頁不能冒用原房主。真正關閉分頁後，瀏覽器是否保留 sessionStorage 亦影響能否恢復；本功能不是跨裝置登入。
- 進行中的牌局仍由原房主瀏覽器主持。原生快照不包含 Promise／事件續行堆疊，不能用重跑 phaseLoop 假裝無損續局。完整房主關頁後接手與伺服器 AI 尚未完成。
- 未更改無名杯技能／AI、自由選角及角色家族互斥，也未改寫 Codify 參考架構。

## 驗證

完整 `npm run verify:local` exit 0：**231 項測試通過**（108 應用、113 引擎／adapter、10 本機 runtime），另 **64 項建置後 HTTP 檢查通過**；Vinext 建置與 TypeScript 成功。最終紀錄為 `outputs/host-lobby-verify.log`，`git diff --check` 通過。

測試包含實際生成的原生開始按鈕、開始確認失敗與重試、雙擊、離頁時同時中止心跳和開局請求、客人忽略舊訊息、重複 host attach 不影響原牌局，以及 start／recover 兩種先後次序。

本機 workerd／SQLite／WebSocket 實際等候超過 60 秒，驗證休眠重載後仍保留房間與成員、客人重新 attach、舊房主遭拒，以及開局狀態在再次休眠後仍不可恢復。第一輪測試在等候期間物件已自行休眠，測試再次強制回收得到「not currently running」；改成先以只讀預檢喚醒，再驗證強制回收，沒有因此縮短離線期限或修改正式判斷。

本輪沒有新版瀏覽器視覺或實體手機驗收，也沒有增加自然完成局數。累計維持單人 10/10、多人 10/10；上述皆為本機連線／流程測試，不算新對局。
