## 正式站操作

登入後使用 `/qa-layout.html`，選完整擴充與手機樣式。DOM 核對根節點含 `grail-phone-layout`，樣式表同時有 `layout/default/phone.css` 與 `grail-phone-controls.css`；這補上前次只有縮小桌面視窗的測試缺口。

- 390×844：4 人選角；設定開啟及關閉，更換候選角色成功。
- 390×667：選神官、第一座位，再次選角後顯示確認。三顆控制外框高度約 44.8px、內層 44px，文字完整且不與選角面板重疊。實際按確認進入牌局，士氣、手牌、技能與五顆頂部工具列按鈕出現，按鈕 44×44px。
- 844×390：同一牌局切橫向後，工具列仍約 44px 高且在視窗內，技能文字完整。橫向整張牌桌仍有角色與計分板擁擠／底部角色裁切的既有問題；不將此測試宣稱為整張橫向牌桌驗收。
- 8 人、390×667：自由選角可開啟／返回；選第八座位、聖殿騎士後，八個座位與更換／自由選角／確定均可見，面板和操作列互不遮擋。

## 檢查與限制

`npm run prepare:engine`、33 項 `test:engine`、`typecheck`、`git diff --check` 通過，Vercel 正式建置成功。首次本機準備失敗是快取上游壓縮檔截斷，重新取得同一固定提交且驗證原 SHA-256 後成功，沒有變更上游版本或 checksum。

瀏覽器為 Chromium，載入真正手機 CSS、保留滑鼠操作；不是實體 iOS Safari，也沒有模擬 Safari 動態網址列或安全區。這一輪驗證按鈕修復，未另跑十場完整對局；先前完整對局紀錄保持獨立。小型原生設定選單仍可開關但尚未全面重新排版。
