# 2026-10-27 HUD 空間避讓第二階段

## 根本風險
舊版 `chooseActionHintTop` 僅沿畫面中央上/下移動；中心席位、士氣戰況、確認/取消、手牌擠滿時，候選位置都碰撞卻仍回傳 `ideal`，於是金色提示可能覆蓋角色或合法操作區。

## 改動
- 新增純函式 `chooseActionHintPlacement`，根據實際可見 viewport、戰況列、本人手牌、原生 `#control`、所有玩家立繪以及浮動圓形工具／牌庫，搜尋中央與左右側的無碰撞矩形。
- 要求至少保留 8～12px 安全留白，優先畫面中央下半部；若中間沒有位置，可向左右移，但不改玩家節點或原生技能按鈕座標。
- 對極短橫向或多名角色擁擠到沒有任何合法空位的情況，`positionActionHint` 回報 false：暫時隱藏新鏡像 HUD，**解除原生被鏡像提示的視覺隱藏**，避免遮住合法目標或「連提示文字都看不到」。
- CSS 的 `left:var(--grail-hint-center-x,50%)` 允許 JS 精準位置但保留樣式 fallback；保留 `pointer-events:none`。
- 不顯示額外卡牌內容，不改引擎選取、技能結算、Cloudflare Worker/DO 或 Vercel。

## 驗收
- 手機直式 390×850：角色區下方、控制列上方的提示不遮任何角色；長句仍可在獨立 HUD 讀取。
- 手機短橫式 844×390：中心被角色擠滿可放左右可用區；任何情況不得蓋住原生確定/取消。
- 極端沒有可用區：原生提示仍能讀，不應消失或導致 JS 例外。
- 以上僅為幾何及 CSS 自動測試，真實 Safari 仍需新一局驗收。
