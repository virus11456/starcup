# 多人加入重試與座位保存：待發布交接

接續使用者「繼續」要求，保留現有規則引擎與房主主持架構；先完成本機驗證、存 GitHub 備份，沿用原定集中部署安排。

## 問題與修改

- 原本 `/online` 加入房間要等 POST 成功回覆後，才把隨機座位 token 寫入 sessionStorage。若伺服器已加入玩家、回覆途中遺失，重試會產生另一個 token：等待中的房間會多佔一席；若房主已開局，則會被當成新玩家而無法加入。
- 新 `enterOnlineRoom` 在加入 POST 前先保存並讀回確認座位識別。重試或同分頁重新載入後沿用同一個 token；保留伺服器原本以 token 辨識既有成員的行為，不增加同步請求、背景輪詢或自動重試。
- 開房前以暫存 key 檢查儲存能力並立即移除。已知無法保存識別時，不消耗開房次數或加入座位；成功開房後保存伺服器所給房間碼對應的識別。加入識別只存在該分頁 sessionStorage，不放入邀請 URL、localStorage 或對外訊息。
- 開房、加入與重連驗證回應的房間碼、暱稱、房名、容量及房主身分；加入／重連必須對應原房間碼。導航只保留必要的公開欄位，不直接保存整個伺服器回應。
- 非 JSON、格式錯誤、網路中斷、儲存阻擋與逾時顯示繁體中文訊息；伺服器提供的房滿、過期、配額等具體錯誤仍保留。重連缺少有效識別時，不送無效要求。
- 原有單一請求鎖、離頁取消、遲到回應不開啟牌局，以及房主原分頁保護仍保留。

## 驗證

- `npm run verify:local` exit 0：**169 項**（95 應用、68 引擎、6 本機 Cloudflare runtime），正式建置與型別檢查成功。紀錄 `outputs/online-entry-verify.log`。
- 新增 9 項應用測試：回覆遺失後沿用識別、儲存 getter／寫入被阻擋或寫入無效時不發 POST、開房探測 key 清除與成功保存、無效房碼／取消、遲到回覆、異常房間資料、HTML／API 錯誤、重連識別／房間驗證、錯誤訊息。
- 新增真實本機 workerd／SQLite HTTP 測試：先讓客人加入持久化成功，再讓房主把房間標為進行中，丟棄第一次客人回覆，透過正式前端 helper 重試。確認仍能以原座位加入、人數保持 **2**，最後正常結束測試房間。這是本機傳輸測試，沒有執行完整牌局、沒有寫入正式資料庫。

- 尚未部署、未做新版瀏覽器畫面與 Safari 實機驗收。自然結算紀錄仍為單人 10/10、多人 6/10；此測試不增加局數。

## 仍需驗收及限制

- 集中部署後檢查朋友從邀請進入、等待期間重試、客人刷新恢復、原房主保護及錯誤訊息；沿用正式用量預算，不以重複正式開房測試一般程式邏輯。
- 本次修復「加入」已完成但回覆遺失的識別問題，**不是建立房間 POST 的冪等化**。開房回覆遺失時，前端仍可能不知道新房間碼；儲存能力也可能在檢查後改變。不得宣稱任意斷線都能找回新開房間。
- 真正房主重新整理／關頁後的規則狀態接手仍未實作，沒有用換房主 ID 或電腦託管冒充伺服器恢復。
- 只更新 `fix/relay-recovery-20261026` 備份，不提前更新 `main`／`cloudflare-migration`，Cloudflare 完成驗收前保留 Vercel。
