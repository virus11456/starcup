# iPhone 直式多人角色卡過度擠壓：座位適應縮放（未部署）

## 原因
使用者 2026-10-27 23:00 台北時間的 iPhone Safari 截圖中，多張非己方角色卡在同一排相互貼疊，紅藍隊伍標記與手牌數也覆蓋鄰近角色。已確認原先的 `grail.css` 對 **600px 以下直式 iPhone** 把所有非己方原生角色卡固定放大至 **1.38 倍**，而釘選 Noname 引擎沒有因此加大座位中心之間的距離。遊戲人數越多，視覺角色與標示越容易互相擠壓。這是介面顯示問題，不是牌張消失、手牌數錯亂或技能規則變更。

## 調整
- `grail-seat-fit.js`：依原生角色節點的 `getBoundingClientRect()`、既有 CSS `scale` 和放大原點，推回原始座位中心；只比較上下位置可能相互遮擋的角色，計算能保留 8px 鄰距的最大放大比例。
- `grail.css`：以 `--grail-portrait-seat-scale` 控制 iPhone 直式角色放大，未完成量測前預設原生比例（1），不再無條件 1.38。
- `grail-bridge.js`：既有 400ms HUD 更新中量測；轉為橫式清掉變數交還原生／既有橫式樣式。角色在四人局仍可充分放大；六、八人局座位太緊時才縮小。
- **所有原生角色節點、CSS transform、原生遊戲座位、卡牌、點擊與目標選擇完全維持原狀。** 不改動技能 filter/content、回合、手牌數及資源。

## 回歸與驗收
- `tests/seat-fit.test.mjs` 模擬 4、6、8 人直式座位、分排座位、左右邊界原點、HUD 定時穩定和旋轉回復，並確認無篡改原生 transform/位置。
- 正式發布前須跑 `npm run verify:local`（完整規則／Cloudflare）、GitHub Actions Chromium 版面測試，並在 iPhone 390/416px 直式、4/6/8 人局確認角色標記不相互遮擋；保留 844×390 橫式與桌面原有大卡佈局。
- 本階段單獨驗證，不用未確認的測試去覆蓋 Cloudflare v57。

## 限制
本次不應把「畫面不同角色彼此靠近」誤判為缺牌；若下次仍發生 HUD 的巨大手牌數標示覆蓋角色，需要在不隱藏公開資訊的前提下另做安全排位調整。
