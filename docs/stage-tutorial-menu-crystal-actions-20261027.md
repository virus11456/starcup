# 2026-10-27 — 新手嚮導、選單入口與水晶換行動

此階段延續 `cloudflare-migration`，尚未獨立部署。與 `stage-gold-breathing-animation-20261027.md` 一起併入下次通過本機完整驗證的 Cloudflare 階段發行。

## 問題與根因

1. 原生「選項 → 新手嚮導」位於 `#window > .menu-container`，原生 `z-index: 8`。新增的固定資訊 HUD 為 `z-index: 20`，開啟教學／選項時 HUD 會壓住原生對話框。
2. 原生 `#arena > #roundmenu` 是浮動漢堡圖示。手機版已將原生「選項」放在頂端常駐系統列，因此浮動圖示重複且遮擋牌桌、角色與行動提示。
3. 風之劍聖「劍影」原生過濾器只判斷非應戰與有水晶／寶石。`gongJiAfter` 觸發時，`xingDong` 會在後續 step 5 才扣除目前行動；判斷時不能把正在結算的那一次誤當成「還剩一點」。原本的 `check` 僅供 AI，不能阻止人類玩家收到無效的水晶消耗提示。

## 改動

- 僅原生選單**開啟**（不含 `.hidden`）時提高至 `z-index: 70`，覆蓋 HUD；保留關閉態原生行為。
- 隱藏冗餘的浮動 `#roundmenu`，維持頂端「選項」及其原生事件、教學、設定功能；不刪除 DOM、選單資料或事件。
- 在引擎準備階段，以既有 `requireOptionalSkillCards` 的 AST 注入方式替「劍影」增加通用判斷：
  - 先扣除**當下正在完成**的行動，再判斷攻擊、法術及共用行動點數是否已耗盡；有排隊中的額外行動亦不提示。
  - 手牌至少有一張未被禁止、並且有合法對象的攻擊牌才可以提示。
  - 仍須通過原生資源條件、非應戰條件；玩家選擇後才走原生 `removeBiShaShuiJing`，不在過濾器中扣資源。
  - 不抑制包含抽牌、產生指示物或其他獨立用途的水晶技能，避免錯改規則。

## 驗證

- 即時已部署版本的 DOM 檢查：`.menu-container.hidden` / 開啟 `menu-container`、對應原生「選項」入口及 `#roundmenu` 存在，原生選單 z8、HUD z20 已實測；修正後的版型待合併部署再做手機視覺驗收。
- `node --test tests/optional-action-guards.test.mjs tests/action-hints.test.mjs` 覆蓋：尚有共用／攻擊／法術／已排隊額外行動、目前行動未扣點、無攻擊手牌、手牌被禁用、無合法目標，以及技能函式可完整序列化至引擎。
- `tests/optional-skill-prompts.test.mjs` 添加原生角色包整合案例，需 `public/engine` 由釘選引擎準備成功後執行。
- `npm run typecheck` 可獨立通過。完整 `npm run verify:local` **仍受釘選引擎封包無法下載（網路 DNS 問題）所阻**，不得當成已通過或逕行發行。

## 部署驗收清單

- 手機直式／橫式開「選項 → 新手嚮導」，文字及關閉按鈕未被計分欄、玩家卡或 HUD 擋住。
- 浮動漢堡不在牌桌中央，頂端「選項」仍能正常開、關、操作所有原生設定。
- 風之劍聖一般行動仍在時打出攻擊，不出現水晶補行動提示、不扣水晶。
- 一般及排隊額外行動均已用完，手上只有法術／不可使用的攻擊／無合法目標時，不出現提示、不扣水晶。
- 一般及排隊行動均已用完，且有可合法打出的攻擊及水晶時，才有**玩家可拒絕**的技能選擇；拒絕不扣水晶、同意才依原生規則扣除並取得一個攻擊行動。
