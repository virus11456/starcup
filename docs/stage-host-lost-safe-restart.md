# 房主永久關頁：安全替代房間（非無損接手）

2026-10-27。當原生引擎房主永久關閉分頁，原生 Promise／GameEvent 續行、牌庫 RNG 及巢狀技能當下區域變數無法從 Cloudflare Durable Objects 的中繼訊息恢復。**本階段不宣稱已完成原局接手。**

## 此次已實作
- guest iframe 只有收到伺服器 `playing && hostAlive=false` 的確認後，才送出同源公開訊號 `grail-host-presence`，僅含房間碼及出席狀態、不夾帶憑證、牌庫或隱藏手牌。
- 外層網站再次確認 `origin`、`event.source === iframe.contentWindow`、房間碼與嚴格的訊號種類，避免其他分頁／iframe 偽造房主失聯。
- 客人可明確選擇「另開新房間（從頭開始）」；二次確認會說明**原局不會接續**，舊局不自動刪除，角色／手牌／牌庫／回合／其他席位都不會轉移。
- 只沿用舊房名、玩家暱稱和 4／6／8 人容量，呼叫原本的 `enterOnlineRoom(type=create)`；保留既有失敗重試、房間建立額度、防重複提交與 private sessionStorage 席位憑證。新局有全新房碼，朋友需重新加入。
- 房主恢復連線時同步收起提示；新房間開啟或離開時清除狀態；不讀取任何其他玩家的私有資料。
- 新增消息來源驗證、非房主門檻、內容限制與房間設定長度的單元測試。

## 無損接手真正還需
1. **全局序列化與確定性重播**：原生事件鏈、任意 await 中的續行、PRNG 狀態、牌庫與棄牌的實際順序、技能暫存與隱藏區域。
2. **伺服器 checkpoint 進度與完整性證明**：每個安全事件邊界簽章存檔，區分已確認輸入、未確認輸出與同一事件去重；不能只用 `get.arenaState()` 的客戶端重連快照。
3. **兩階段接手與雙房主 fencing**：房主租約失效、候補持有同代次完整 checkpoint、原子交接，舊連線代次及所有過期選擇都不得恢復；建立新引擎後還要重建各席位 native init/reinit。
4. **難局真實驗收**：魔彈鏈、插入回合、恢復階段技能、選牌／應戰中斷、手機背景凍結與八人完整自然結算；必須在原局繼續而非重開。
