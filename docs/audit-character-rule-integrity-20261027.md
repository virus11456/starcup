## 已確認：先前的「缺牌時不讓發動」過濾器不符合卡面時機

共七項曾於 `scripts/prepare-engine.mjs` 向釘選原始 `filter` 額外注入「目前是否有對應手牌／目標／剩餘行動」條件，現已撤回，不更改原生結算與玩家選擇：

| 角色／技能 | 原卡面的合法發動時機 | 先前額外限制的問題 |
|---|---|---|
| 風之劍聖「劍影」 | 攻擊行動結束後付水晶，取得一次攻擊行動 | 要求先耗盡一般及排隊行動，且當下有合法攻擊牌；卡面並無此要求 |
| 風之劍聖「風怒追擊」 | 攻擊行動結束後，額外風系攻擊 | 把當下握有風系攻擊牌當成技能合法性 |
| 魔劍士「修羅連斬」 | 攻擊行動結束後，額外火系攻擊 | 把當下握有火系攻擊牌當成技能合法性 |
| 劍之魔女「技之劍意」 | 攻擊行動結束時，額外技類攻擊 | 把當下握有技類攻擊牌當成技能合法性 |
| 特典「二重劍影」 | 攻擊命中且攻擊行動結束時，額外同系攻擊 | 把當下握有同系牌當成觸發資格 |
| 嫉妒少女「虛榮掌握」 | 主動攻擊命中時，額外魔彈法術行動 | 把當下握有魔彈或可轉換的牌當成觸發資格 |
| 嫉妒少女「嫉妒追放」 | 攻擊／法術行動後付水晶，取得限定目標的攻擊行動 | 當下有攻擊牌並非卡面條件；原先將「目前存在合格對手」也提前檢查，應再依「丟失目標」規則核實，而非混在缺牌過濾內 |

注意「風之劍聖」舊版 `san_fengZhiJianSheng` 仍引用共用 `jianYing` 等技能，稽核時不能只看新版角色登記。

**關鍵區別：**技能是否有權「在卡面時機取得額外行動」，與額外行動執行時是否有合格牌、目標，是不同的檢查點。只在後者才能套用卡片或目標的合法性；不能把它搬到前者提前禁止玩家發動。

## 同類型、仍符合原卡面時機的技能

- `shiZhouNian/faLiChaoXi`「法力潮汐」：法術行動結束後付水晶，額外法術行動。`check` 的 `canFaShu` 是 AI 評估，不能變成玩家觸發條件。
- `shiZhouNian/jieJiaoJieZao`「戒驕戒躁」：符合指定狀態的攻擊／法術行動後付水晶、重置並取得共用行動；移除狀態亦是效果，不能因暫時沒牌而藏掉。
- `shiZhouNian/buQuYiZhi`「不屈意志」：付水晶後抽牌、加劍氣並給予攻擊行動。抽到的牌可能剛好供新增行動使用，先檢查原本手牌會特別錯誤。
- `teDian/jianCanYing`「劍殘影」：付水晶後指定敵手棄牌並給予目標受限的攻擊行動，不等於「現在有可用攻擊」才准發動。
- `yiDuanYeHuo/touXi`「偷襲」：技能先要求兩張魔力瓶及資源；額外攻擊只是其中一種可能結果，不能只看是否有攻擊牌就限制技能。

這些技能本次**不改原始規則**，也不把「當下沒有牌」單獨判定為程式錯誤。

## 規則對照後已排除的誤判：強制棄牌不足仍可部分發動

玩家整理規則書「角色技能 → 技能發動條件與效果」區分了**發動條件**與**效果未完全實現**。前者未滿足不能發動；後者即使只能做部分效果，仍可能合法。規則書特別以「神聖領域」為例，指出神官**零手牌仍能發動**，若只有一張手牌，則棄掉一張。這與釘選引擎的強制棄牌自動選擇行為一致，不能誤當成費用漏洞而加入「至少兩張手牌」限制。

| 角色／技能 | 程式流程 | 稽核判斷 |
|---|---|---|
| 劍之魔女「劍影・斷念」 (`teDian.js:223`) | 已有寶石即可提示；同意後先扣寶石，再 `chooseToDiscard(2, true)`，摸一、追加攻擊 | 卡面「棄兩張」處於效果敘述；不應自動加入至少兩張手牌限制。實際少牌結算仍需 UI 測試 |
| 神聖領域 (`shiZhouNian.js:4709`) | 法術支付水晶後，強制棄兩張手牌，再選傷害或治療 | **規則書明確確認零／一手牌仍可發動；非漏洞** |
| 倒逆之蝶 (`shiZhouNian.js:9120`) | 法術支付水晶後，強制棄兩張牌，再選效果 | 依效果不完全發動原則，不能貿然加入手牌門檻；尚需實戰測試 |
| 血之詛咒 (`shiZhouNian.js:8866`) | 先造成法術傷害，之後強制棄三張 | 棄牌在傷害之後是效果次序，不是預付成本；不能倒置或提前加門檻 |

釘選引擎的 `chooseToDiscard(n, true)` 會在數量不足時走強制選取所有可棄牌的分支；**規則與原始行為相符的案例必須保留，不能單憑數量不足就禁止**。

## 尚待實戰核實的問題

- **丟失目標**：整理版規則指出，若技能發動時根本沒有合法目標，不能發動；但目標合法、效果只有部分實現時仍可發動。需要針對具有指定對手或隊友的技能，在 1v1／角色陣亡等邊界場景驗證 `filterTarget` 和 `chooseTarget`，例如「劍殘影」、「嫉妒追放」及「神聖領域」的隊友分支。
- **提示與能量支付時序**：技能 `filter` 是否僅檢查合法發動；由玩家決定是否支付，取消後不能扣水晶。需在生成引擎中觀察完整選擇／取消流程。
- **只留下顯示提示的優化**：如果手上暫無可用牌，可以顯示「目前缺少可用牌，但依規則仍可發動」等提示；不能自動略過合法反應。

## 不變更的界線與後續

1. 不修改角色文字、原生 `trigger`、資源花費、合法目標、行動數、對戰勝負邏輯。
2. 優先透過 UI 顯示效果與發動時機說明來減少困惑；**不以手牌推測替玩家拒絕合法技能**。
3. 將強制棄牌、目標條件及取消支付分別測試：0／1／2／3 張牌、寶石或水晶不足、能否取消、多人對手與 1v1。
4. 正式上線前要有釘選引擎產物及 `verify:local`、再做手動對局。當前工作環境無法取得引擎壓縮檔，尚不能宣稱上述實戰全部通過。
